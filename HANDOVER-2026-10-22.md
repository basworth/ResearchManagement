## What shipped and is verified live today

**Server side (all deployed and tested against the live function):**

- **The research feed was never being stored.** `items` is `PRIMARY KEY (id)` — id alone, not
  (id, kind) — and the function wrote the feed and the config to the *same* id, so the config
  overwrote the feed every run. It reported `ok, 8 papers` every time and left nothing behind.
- **Edge-function CORS** widened to the headers supabase-js sends. **This fixed a latent hazard,
  not an outage** — I wrongly told Adam it had broken invites etc. for everyone. The app calls
  every function with plain `fetch` and only `Content-Type` + `Authorization`, which were always
  allowed. Only `sb.functions.invoke()` was affected, and nothing in the app uses it.
- **Three PubMed query bugs**, each returning a believable-but-wrong small result set:
  1. `A AND NOT (B)` **requires** B in PubMed. 40 results → 2.
  2. Quoted author terms kill initial expansion. `Cole B[Author]` 556 vs `"Cole B"[Author]` 23.
     **Adam's own feed had been anchoring on 3 papers instead of 20.**
  3. Phrase-wrapping a whole typed query makes it an exact-phrase search.
- **`frameError`** now reports *why* framing degraded. `framed:false` previously meant four
  different things and threw the reason away.
- **`max_tokens` 4000 → 16000**, and `stop_reason` is checked before parsing.
- **ANTHROPIC_API_KEY is set and working.** It must be **workspace-scoped**, not org-scoped — an
  org key is rejected by the Messages API. A new secret needs a function redeploy to be picked up.

**Feeds seeded and run for all five labs** (own-papers anchoring each): sports-yanke 20,
spine-singh 20, sports-chahla 20, sports-cole 20, spine-park 5. Topics drafted from what each
